# Deployment

The site is a static build hosted on Vercel through the GitHub integration of `boobaGreen/agileCourse`.

| Environment | Trigger | URL |
|---|---|---|
| Production | Push or merge to `main` | https://agile.claudiodallara.it |
| Preview | Push to any other branch, or open a pull request | Generated by Vercel, shown on the pull request and in the Vercel dashboard |

## Vercel project settings

| Setting | Value |
|---|---|
| Root directory | `app` |
| Framework preset | Vite |
| Install command | `npm install` |
| Build command | `npm run build` (runs `tsc -b` then `vite build`) |
| Output directory | `dist` |
| Node.js | 20 or later |

`app/vercel.json` rewrites every path to `index.html`, so deep links such as `/docker/module/docker-3` work on reload.

## Release checklist

1. `npm ci && npm run build` passes locally with no type errors.
2. Open the preview deployment and walk through: landing, dashboard, one module per track with its lab and quiz, a cheat sheet, the profile.
3. Check light and dark themes, English and Italian, and a phone-width viewport.
4. Update `CHANGELOG.md` and the `version` field in `app/package.json`.
5. Merge to `main`. Vercel promotes the build to production.

## Going back to version 1

Version 1 is preserved in two places:

| Reference | Points to |
|---|---|
| Tag `v1.1.0` | The last v1 commit, frozen |
| Branch `v1-legacy` | Same commit; Vercel keeps a preview deployment of it online |

To put version 1 back in production quickly, use the Vercel rollback below and promote the last v1 production deployment. To make it permanent, reset `main` to the tag with a revert or merge, never with a force push to a shared branch:

```bash
git checkout main
git revert --no-commit v1.1.0..HEAD
git commit -m "revert: back to v1.1.0"
git push origin main
```

## Rollback

In the Vercel dashboard, open the project, go to Deployments, pick the last good production deployment and choose "Promote to Production". The rollback is instant and does not require a new commit. Revert the offending commit on `main` afterwards so the next deployment does not reintroduce it.

## Learner data

Progress is stored in each learner's browser under `learning-platform-v1`. Deployments never touch it. Changing that key, or changing the shape of the stored object, resets progress for everyone; add a `persist` migration instead.
